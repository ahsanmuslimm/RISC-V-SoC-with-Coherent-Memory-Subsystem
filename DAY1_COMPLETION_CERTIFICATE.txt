ARCHITECTURE OVERVIEW
================================================================================

Single-Cycle Datapath (RV32I):

  PC → I-SRAM (async read, 0 latency)
   │
   ├─ Instruction [31:0]
   │
   ├─ Control Unit (decode all 37 instructions)
   │
   ├─ Register File (async read RS1, RS2)
   │
   ├─ ALU (combinational, 10 operations)
   │
   ├─ Write-back Mux (ALU result / load data / PC+4)
   │
   ├─ Register File Write (sync @ posedge clk)
   │
   └─ PC Update (sync @ posedge clk)

Memory Interface:
   ├─ RUN state: fetch & execute normally
   └─ STALL_MEM state: wait for dmem_ack (then return to RUN)

KNOWN LIMITATIONS & DESIGN DECISIONS
================================================================================

Scope (Intentional):
  ├─ No pipeline (single-cycle simpler, meets 20 MHz)
  ├─ No forwarding (not needed without pipeline)
  ├─ No branch prediction (dynamic branch acceptable)
  ├─ No privileged mode (not needed for capstone)
  ├─ No virtual memory (direct mapping sufficient)
  └─ No FPU (RV32I base-integer only)

Trade-offs (Documented):
  ├─ Single-cycle: simpler control, lower clock frequency OK
  ├─ Direct-mapped cache: simpler than set-assoc, sufficient for demo
  ├─ Write-through: simpler than write-back, no dirty tracking
  ├─ Sideband coherence: orthogonal to AXI, bounded latency
  └─ Register arrays for SRAM: avoids macro integration risk

Decisions (7 Locked + 9 Refinements):
  ✅ D1: Single-cycle core with req/ack stall
  ✅ D2: AXI4-Lite only (no burst)
  ✅ D3: Write-through + write-allocate
  ✅ D4: 3-state I/S/M coherence
  ✅ D5: Direct-mapped, 4 lines
  ✅ D6: Async reset, 2-FF sync release
  ✅ D7: Register arrays (no OpenRAM)
  ✅ R1–R9: Spec gap refinements (see logic_design/01)
